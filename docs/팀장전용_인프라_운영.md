# 팀장 전용 — 인프라 운영

> **이 문서는 팀장(김세현)만 보는 문서입니다.**
> 팀원용 안내는 [`AWS_구축_가이드.md`](AWS_구축_가이드.md) 를 보세요.
>
> 왜 나눴나 — Terraform 은 변수 하나만 빠뜨려도 서버가 전부 꺼집니다.
> 팀원이 GPU 를 켜는 방법을 알 필요도 없고, 알면 실수로 하루 7만원이 나갑니다.
> 그래서 **인프라를 바꾸는 모든 것은 이 문서에, 서버 안에서 하는 일은 팀원 문서에** 둡니다.

---

## 1. 계정과 키

**계정** `Network_Class_1` (IAM User 하나를 팀 전체가 공유)

액세스 키는 IAM User 하나당 **최대 2개**입니다. 그래서 이렇게 나눠 씁니다.

| 키 | 용도 | 폐기 시점 |
| --- | --- | --- |
| `AKIA...2JSV7HHA` (설명 `kisia-net1-cli-sehyeon`) | **팀장 전용.** Terraform 이 이걸로 동작 | 인프라 완전 정리 후 마지막 |
| `AKIA...4PCIS3UV` | **팀 공용.** 팀원들의 SSM 접속 | 프로젝트 종료 시 먼저 |

**팀 공용 키를 팀장 키와 섞지 마세요.** 공용 키가 유출되면 그것만 폐기하면 되고, Terraform 은 계속 돌아갑니다. 하나로 합치면 사고가 났을 때 서버를 끌 수단까지 같이 사라집니다.

시크릿은 `%USERPROFILE%\.aws\credentials` 에 평문으로 있습니다. 이 파일을 저장소 폴더에 두거나 캡처하지 마세요.

### 현황 확인

```powershell
aws iam list-access-keys        # 키 목록과 생성일
aws iam list-mfa-devices        # MFA 등록 상태
aws sts get-caller-identity     # 지금 내가 누구로 붙어 있나
```

### 알려진 이슈

- **콘솔 MFA 가 팀원 폰에 묶여 있습니다** (`peter`, 2026-08-30 등록). 콘솔 작업이 필요하면 그분께 코드를 받아야 합니다. CLI 는 MFA 를 안 거치므로 영향 없습니다.
- 근본 해결은 담당자께 **팀원별 IAM User** 를 요청하는 것입니다. 그러면 CloudTrail 에 누가 무엇을 했는지 남습니다. 지금은 공용 키라 추적이 안 되고, 카톡 기록이 유일한 단서입니다.

## 2. Terraform 구조

```
infra/terraform/
  backend.tf              S3 원격 state (팀 공용), 잠금
  variables.tf            모든 변수
  network.tf              VPC · 서브넷 · IGW · NAT
  iam.tf                  SSM 접속용 IAM Role
  security.tf             GPU 서버 방화벽
  security_servers.tf     siem / web / vm 방화벽
  llm.tf                  GPU 서버
  servers.tf              siem / web / vm
  mirror.tf               트래픽 미러링 (기본 꺼짐)
  outputs.tf              GPU 관련 출력
  outputs_servers.tf      서버 3대 출력
  setup.ps1               ⚠ 최초 1회용. 다시 실행 금지
```

### 스위치가 두 개입니다

```hcl
var.lab_running    # GPU 서버 (하루 약 7만원)
var.siem_running   # siem · web · vm (셋이 함께, 하루 약 $9.5)
```

NAT 게이트웨이는 **둘 중 하나라도 켜져 있으면 유지**되고, **둘 다 꺼져야 삭제**됩니다.

```hcl
locals { nat_needed = var.lab_running || var.siem_running }
```

NAT 은 상태가 없는 자원이라 지웠다 만들어도 잃는 게 없습니다. 대신 켤 때 2~3분 더 걸리고, 나가는 공인 IP 가 매번 바뀝니다.

### ⚠️ 변수를 항상 둘 다 넘기세요

```powershell
terraform apply -var siem_running=true -var lab_running=false
```

하나만 넘기면 나머지는 기본값 `false` 가 적용됩니다. **GPU 켜려다 팀원들 작업 서버를 내려버리는 사고**가 여기서 납니다.

## 3. 켜고 끄기

```powershell
cd <repo>\infra\terraform

# 팀원 작업용 — 서버 3대만
terraform apply -var siem_running=true

# 모델 분석까지 — GPU 추가
terraform apply -var siem_running=true -var lab_running=true

# 전부 끄기 ★ 매일 마지막에
terraform apply -var siem_running=false -var lab_running=false
```

### 켠 뒤 확인

```powershell
aws ssm describe-instance-information --query "InstanceInformationList[].{ID:InstanceId,Ping:PingStatus}" --output table
terraform output web_public_ip     # 켤 때마다 바뀝니다
```

`Online` 이 뜨기까지 부팅 후 1~2분 걸립니다. 5분이 지나도 안 나오면 NAT 또는 IAM 문제입니다.

## 4. 인프라를 바꿀 때

```powershell
terraform init      # 새 리소스 타입이 생겼을 때만
terraform plan      # ★ 반드시 눈으로 확인
terraform apply
```

`plan` 에서 볼 것은 딱 두 가지입니다.

| 확인 | 정상 |
| --- | --- |
| `to destroy` | **0** |
| `aws_instance.llm` | 목록에 **없음** |

`llm` 이 `destroy` 나 `replace` 로 잡히면 **거기서 멈추세요.** 받아둔 모델 40GB 가 날아갑니다.

### 바꾼 뒤에는 반드시 커밋

state 는 S3 에 있고 코드는 로컬에만 있습니다. 코드를 안 올리면 팀원이 `terraform plan` 을 돌렸을 때 **"코드에 없는 서버가 state 에 있네"** 로 판단해 `destroy` 를 제안합니다.

```powershell
git add infra/terraform docs
git commit -m "infra: <무엇을 왜 바꿨는지>"
git push origin main
```

## 5. GPU 서버 (vLLM)

### 실전에서 확인된 값

| 항목 | 값 | 이유 |
| --- | --- | --- |
| `--max-model-len` | **32768** | 8192 로는 증거 번들이 안 들어가 400 오류 |
| 인스턴스 | `g6e.xlarge` (L40S 48GB) | 쿼터 8 vCPU 기준 4 vCPU 한 대 |
| 디스크 | 200GB | 모델 40GB + 도커 이미지 + 여유 |
| `docker run` 인자 | **`serve` 를 넣지 말 것** | 이미지 진입점에 이미 포함 |

### 순서

```powershell
terraform apply -var lab_running=true
# 2분 대기
aws ssm start-session --target <llm 인스턴스 ID>
```

```bash
sudo su - ubuntu          # SSM 은 ssm-user 로 붙습니다. docker 권한이 없어요
nvidia-smi                # GPU 가 보이는지 ★ 여기서 실패하면 진행 금지
sudo docker ps -a
sudo docker logs --tail 30 hawki-vllm
```

### 터널

```powershell
aws ssm start-session --target <llm ID> --document-name AWS-StartPortForwardingSession --parameters portNumber=8000,localPortNumber=8000
```

**이 창은 열어둔 채로 두세요.** 닫으면 연결이 끊깁니다. `cmd` 는 따옴표가 깨지니 PowerShell 을 쓰거나 위 형식(`key=value`)을 쓰세요.

확인 (다른 창에서)

```powershell
curl.exe -H "Authorization: Bearer <LLM_API_KEY>" http://127.0.0.1:8000/v1/models
```

`{"error":"Unauthorized"}` 는 **실패가 아닙니다.** 서버는 살아 있고 키를 안 넣은 것입니다.

## 6. 비용

| 항목 | 켜져 있을 때 | 꺼도 나가는 것 |
| --- | --- | --- |
| GPU `g6e.xlarge` | 하루 약 7만원 | — |
| 서버 3대 + NAT | 하루 약 $9.5 (1.3만원) | — |
| 디스크 380GB | — | **월 약 $35** |

예산은 월 $200 이고 AWS Budgets 알림이 걸려 있습니다. 매일 마지막에 끄는 것이 유일한 실질적 방어입니다.

```powershell
aws ec2 describe-instances --filters "Name=instance-state-name,Values=running" --query "Reservations[].Instances[].{Name:Tags[?Key=='Name']|[0].Value,ID:InstanceId,Type:InstanceType}" --output table
```

**태그가 아니라 상태로 거른 이유** — Terraform 밖에서 만들어진 인스턴스까지 보이게 하려고요. 실제로 우리 state 에 없는 서버가 두 대 떠 있는 것을 이 명령으로 발견했습니다.

### Terraform 밖 자원

| 이름 | ID | 상태 |
| --- | --- | --- |
| `ai-security-gateway` | `i-0a8b8aee6f3d24a36` | Terraform 관리 밖. 용도 확인 필요 |

## 7. 절대 하지 말 것

**`setup.ps1` 재실행** — S3 버킷을 새로 만들고 `backend.tf` 를 덮어씁니다. state 가 갈라져서 인프라가 통째로 두 벌이 되고 요금이 두 배가 됩니다. 최초 1회용입니다.

**팀장 키를 팀원에게 공유** — 급할 때 "그냥 내 거 줄게" 가 되기 쉽습니다. 그 순간 키 분리가 무너집니다.

**IAM 권한 확대** — 지금 서버들의 권한은 `AmazonSSMManagedInstanceCore` 하나뿐입니다. 서버가 털려도 새 인스턴스를 못 만드는 마지막 방어선이에요. 편하다고 `AdministratorAccess` 를 붙이면 이게 사라집니다.

**보안 그룹 임의 개방** — 교육용 계정 지침상 `0.0.0.0/0` 은 사전 확인 대상입니다. `web` 의 80/443 은 SIEM 프로젝트 특성상 의도적으로 열어두었고 담당자께 알린 사항입니다.

## 8. 사고 대응

인증정보 유출이 의심되거나 모르는 리소스가 보이면:

1. **아무것도 삭제하지 마세요.** 증거가 사라집니다
2. 타임라인을 먼저 뽑습니다

```powershell
aws iam list-access-keys
aws iam list-mfa-devices
aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=CreateAccessKey --max-results 5
aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=RunInstances --max-results 10
```

`sourceIPAddress` 를 보면 국내인지 외부인지 갈립니다.

3. 팀원에게 먼저 확인합니다 (대개 여기서 풀립니다)
4. 팀 누구도 아니면 **즉시 담당자께 공유**합니다. 비밀번호나 키만 바꾸고 넘어가지 마세요

## 9. 팀장이 넘기는 것 / 넘기지 않는 것

| 넘긴다 | 넘기지 않는다 |
| --- | --- |
| 인스턴스 ID | Terraform 실행 권한 |
| SIEM 사설 IP (`10.0.10.123`) | 팀장 액세스 키 |
| 팀 공용 액세스 키 (개인 DM) | GPU 켜고 끄는 방법 |
| 서버 접속 방법 | S3 state 접근 |

경계는 이 한 줄입니다 — **팀장은 빈 서버를 접속 가능한 상태로 만들어 넘기고, 그 안에 무엇을 설치할지는 담당자가 정한다.**
