# 역할 분담 (2026-08-25 멘토링 Action Items 기준)

**구성** SIEM 서버 1대 · 로그 수집 VM 1대 · LLM 서버 1대 (구축 완료)
VM 은 내부 네트워크의 가상 컴퓨터 한 대입니다. 여기서 실제 로그가 나오고, Agent 가 그걸 SIEM 으로 보냅니다.
**VM 은 공용입니다.** ⑥이 VM 자체(OS·Agent·전송)를 맡고, 그 위에 ③이 Suricata 를, ④가 웹서버+WAF 를 올립니다.

각자 **체크리스트 항목 + 구축 1개 + 발표 산출물 1개** 를 가집니다.

## ① 아키텍처 · SIEM — 권민석

- [ ] 구성도 마무리 (1·2·3·4) — **거의 완료**
- [ ] 로그 전송 에이전트 명칭 멘토님께 재확인 (13)
- [ ] **Wazuh Manager · Indexer · Dashboard 설치 및 설정**
- [ ] VM 의 Agent 를 Manager 에 등록하고, 로그가 실제로 올라오는지 확인
- [ ] 구성도에 그린 대로 로그가 들어오는지 대조 — 다르면 그림을 고칠 것

**끝났다는 기준** Wazuh 대시보드에 VM 로그가 뜨고, 그 화면과 구성도가 일치함

> 구성도를 그린 사람이 SIEM 을 맡는 이유 — 멘토님이 "구성도를 도메인 지식으로 가진 사람이 사고 대응에 반드시 포함된다" 고 하셨습니다. 그림과 실물을 같은 사람이 붙들고 있어야 둘이 안 어긋납니다.

## ④ 경보 설계 — 담당: (        )

- [ ] 경보 룰 3종 정의 (7) — SQLi 문자열 / IP 기반 / **WAF탐지 + 웹서버 200 상관분석**
- [ ] 공격 유형별 시간 윈도우 정의 (10) — brute force 1~5분 / 회피형 3일 / 장기 1주
- [ ] VM 에 웹서버 + ModSecurity 설치
- [ ] 정의한 룰을 실제로 SIEM 에 등록해서 경보가 뜨는지 확인
- [ ] brute force 시나리오 제작 — 멘토님이 예로 드셨는데 우리한테 없음

**끝났다는 기준** 401 반복 → 200 한 번이 담긴 로그에서 "1건 성공" 경보가 실제로 뜸

> 3번 룰이 핵심입니다. WAF 가 잡았는데 웹서버가 200 이면 통과, 403/404 면 막힘. 단일 장비로는 못 하는 판단이고, 우리가 상관분석을 하는 이유 그 자체입니다.
